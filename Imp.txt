 1. Problem Statement
The objective of this research is to design, implement, and evaluate a domain-adaptive, low-latency conversational speech AI framework. Current conversational AI systems face a strict dichotomy. Cascaded systems are computationally efficient but suffer from Acoustic-to-Semantic Error Cascading in domain-specific conversations, where transcription errors propagate directly into downstream reasoning. Conversely, unified Audio-LLMs preserve richer acoustic semantics but require significantly higher computational resources and exhibit higher inference latency, making them difficult to deploy in real-time edge applications. Existing speech pipelines lack an intermediate semantic intelligence layer capable of understanding the uncertainty, intent, dialogue context, and domain semantics of spoken utterances before reasoning.
2. Proposed Methodology: Adaptive Semantic Intelligence Layer (ASIL)
The proposed framework introduces an Adaptive Semantic Intelligence Layer (ASIL) between the Automatic Speech Recognition (ASR) system and the downstream Large Language Model (LLM). The complete framework is designed as an inference-time semantic correction layer deployable on edge hardware without retraining the underlying foundation models.

Step 1: Shared Speech Encoding & Parallel Execution
The input speech waveform is first processed using the frozen Whisper encoder. To minimize sequential latency accumulation, the pipeline branches immediately after the encoder. The following modules execute in parallel: the Whisper Decoder, the Shared NLU Head, Beam Candidate Extraction, and Context Memory Update. The pipeline only synchronizes after these branches complete, directly before confusion estimation. The Whisper model itself is not fine-tuned, ensuring the framework remains entirely domain-independent.
Step 2: Lightweight Shared NLU Head
The NLU must not operate on the ASR transcript. The NLU operates directly on contextual acoustic embeddings generated by the frozen Whisper encoder before transcription, thereby avoiding propagation of transcription errors. The NLU strictly reuses Whisper encoder features, ensuring no additional speech encoder is introduced.
Classification: The multi-task network contains only four heads: Domain Classification, Intent Classification, Entity Type Classification, and Urgency Classification. NLU confidence is not computed via a dedicated head; it is simply the Maximum Softmax Probability obtained from each classifier.
Training Protocol: Training data is created by combining publicly available intent classification datasets together with domain-specific datasets and synthetically generated speech. Examples include Medical (MedDialog, HealthCareMagic, MTSamples), Finance (Banking77, FiQA), and General (SNIPS, ATIS). This text is converted to speech using XTTS, passed through Whisper, encoder embeddings are extracted, and only the lightweight MLP is trained while Whisper remains frozen.
Step 3: Rolling Context Memory & ASR Confidence Estimation
ASR Confidence: We do not compute utterance confidence using average token confidence. Instead, critical domain entities receive higher importance. Utterance confidence is computed using a weighted minimum (or minimum over critical entities) so that one low-confidence medical entity is not hidden by many highly confident common words.
Context Injection: At the end of every turn, dialogue history is injected into three different stages: Candidate Generation, Knowledge Retrieval, and Semantic Reconciliation, heavily influencing filtering and semantic validation.
Beam Extraction: Top Beam Candidates are preserved as temporary semantic hypotheses. They are NOT inserted into the Knowledge Pack. Later they are merged with Knowledge candidates and Embedding candidates during semantic reconciliation.
Step 4: Intent-Aware Context-Guided Candidate Generation
Candidate generation combines three distinct pools: Top Beam Candidates \cup Embedding Neighbours \cup Knowledge Pack Candidates.
To dramatically reduce false positives, the combined candidate pool is filtered using three sequential semantic filters:
Filter 1: Entity Type Compatibility
Filter 2: Intent Compatibility
Filter 3: Conversation Context Compatibility
Only candidates passing all three filters proceed further. This explicitly reduces false positives.
Step 5: Multi-Layer Knowledge Interaction
Instead of loosely relying on "domain terminology," the Knowledge Pack functions as a highly structured semantic validator explicitly defined by six layers:
General English vocabulary
Domain terminology
Abbreviation dictionary
Domain ontology
Common ASR confusion pairs
Precomputed entity embeddings
The NLU prediction first determines the Domain, Intent, and Entity Type. Only then is the corresponding subset of the Knowledge Pack searched, which drastically minimizes latency.
Step 6: Adaptive Confusion Index Computation
The multi-variate Confusion Index represents the final routing mechanism prior to reconciliation. Every uncertainty term is computed precisely:
ASR Uncertainty: Weighted entity confidence.
NLU Uncertainty: Maximum softmax uncertainty.
Knowledge Disagreement: Difference between top two retrieval scores.
Context Disagreement: Cosine similarity between candidate embedding and dialogue context embedding.
These normalized values become the input features of the lightweight Attention Fusion Network that estimates the final Confusion Index. Note that NLU predictions are treated only as probabilistic priors. They never make hard decisions; other evidence sources can override incorrect NLU predictions, effectively preventing cascading errors.
Step 7: Hierarchical Sub-Utterance Routing (Acoustic Expert)
Instead of invoking Gemma immediately whenever confusion exceeds a threshold, the ASIL implements a strict hierarchical routing strategy featuring three distinct paths:
Fast Path: High confidence, Knowledge agrees, Context agrees \rightarrow Accept directly. No correction.
Knowledge Path: Moderate uncertainty, Knowledge retrieval produces one dominant candidate with a high retrieval margin \rightarrow Correct directly. No Gemma.
Acoustic Expert Path: Only when Knowledge, Context, and NLU still disagree \rightarrow Invoke Gemma Audio.
Gemma is therefore expected to run only on a very small percentage of utterances. When invoked, the pipeline does NOT send only audio. Instead, it sends a 1–3 second uncertain audio segment, the surrounding transcript, the candidate list, and a short conversation summary. Gemma's task is semantic disambiguation rather than full reasoning, and it runs asynchronously.
Step 8: Adaptive Semantic Reconciliation
During final reconciliation, every surviving candidate becomes one numerical feature vector. Example features include: ASR Confidence, Beam Rank, Embedding Similarity, Knowledge Similarity, Context Similarity, Intent Compatibility, Entity Compatibility, Domain Compatibility, and the Acoustic Expert Score (optional).
The Attention-based Evidence Fusion Network learns to assign adaptive importance to different evidence sources instead of relying on manually selected heuristic weights. The highest scoring candidate becomes the final semantic hypothesis.
The downstream LLM never receives the raw uncertain ASR transcript; instead, it receives a corrected Semantic Intelligence Packet.
3. False Positive Reduction
False positives and domain hallucinations are aggressively minimized through gating. Every candidate must explicitly satisfy entity compatibility, intent compatibility, and dialogue context compatibility before entering semantic reconciliation. Furthermore, semantic reconciliation itself provides another probabilistic verification stage.
4. Latency Optimization
Sequential latency accumulation is circumvented. After the Whisper encoder, the following modules execute in parallel: Whisper Decoder, Shared NLU, Beam Candidate Extraction, and Context Memory Update. Only after these branches complete does the pipeline synchronize before confusion estimation, mathematically minimizing sequential latency accumulation.
5. Architectural Novelty
Do NOT claim Whisper encoder sharing, multi-task learning, attention, knowledge retrieval, or confidence estimation as individual novelties. Instead, the novelty lies in the unified Adaptive Semantic Intelligence Layer (ASIL), which jointly integrates shared speech representations, lightweight speech-aware NLU, intent-guided candidate generation, hierarchical knowledge interaction, adaptive three-path routing, selective sub-utterance Audio-LLM invocation, and attention-based semantic evidence fusion into a single inference-time semantic intelligence framework.
6. Feasibility
The ASIL framework is computationally feasible for edge deployment. Only the lightweight MLP and Attention Fusion Network require training, while Whisper remains completely frozen. No additional speech encoder is introduced, and Gemma Audio executes only in the Acoustic Expert Path. Average latency therefore remains close to the original cascaded pipeline while providing substantially improved semantic robustness.
